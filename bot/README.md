# Telegram-бот Eternity-1 — привязка аккаунтов (инструкция покупателю)

Простой бот для привязки Minecraft-аккаунта к Telegram и управления им.
Игрок сам привязывает аккаунт и может сбросить пароль, кикнуть сессии,
включить лицензию и 2FA — прямо из Telegram.

---

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и инструкция по привязке |
| `/bind [НИК] [ПАРОЛЬ]` | Привязать аккаунт к этому Telegram |
| `/list` | Список привязанных аккаунтов |
| `/recovery [НИК]` | Сбросить пароль от аккаунта |
| `/license [НИК]` | Включить/отключить режим лицензии |
| `/2fa [НИК]` | Включить/отключить подтверждение входа |
| `/kick [НИК]` | Кикнуть аккаунт с сервера |
| `/accounts` | (только владелец) все привязанные аккаунты на сервере |

Пароль, который игрок вводит в `/bind`, бот **не показывает** поддержке
(хранится только в виде хэша). Действия `/recovery` `/license` `/2fa`
`/kick` работают только с аккаунтами, привязанными именно к этому Telegram,
— нельзя управлять чужим ником. Команда `/accounts` видна только владельцу
(чей `OWNER_TELEGRAM_ID` указан в `.env`) — она показывает все ники и их
Telegram-ID, то есть полный список привязок на сервере.

## Быстрый старт (3 шага)

1. **Токен бота:** у @BotFather `/newbot` → скопируй токен; у @userinfobot
   узнай свой Telegram ID.
2. **Запуск:** `bot\setup.bat` (вставь токен + ID, ставит зависимости),
   потом `bot\start-bot.bat` (окно держи открытым).
3. **Сервер:** положи `plugin/dist/TelegramLink.jar` в `plugins/`, перезапусти
   сервер. В `plugins/TelegramLink/config.yml` укажи `bot_link` (ссылка на бота,
   напр. `https://t.me/ETERNITY_3_2FA_bot`). При входе игрок увидит ссылку.

Готово. Игрок пишет `/start` боту и привязывает аккаунт.

> **Важно:** один и тот же `BOT_TOKEN` нельзя запускать в два экземпляра —
> будет ошибка конфликта (409) и бот не будет получать сообщения. Запущен
> только один `start-bot.bat`. Если окно бота закрывается сразу — оно теперь
> не закрывается, а показывает ошибку (в конце `pause`); прочитай текст ошибки.

## Как пользуются игроки

1. Игрок пишет боту `/start` → получает инструкцию.
2. Вводит `/bind [Ник] [Пароль]` (свой пароль от аккаунта на сервере).
3. Аккаунт привязан. Дальше по ситуации:
   - Забыл пароль → `/recovery [Ник]` → бот даёт новый пароль.
   - Аккаунт «угнали» → `/kick [Ник]` (сбросить сессии), затем `/recovery`.
   - Нужна лицензия/2FA → `/license [Ник]` или `/2fa [Ник]`.

## Настройка (`bot/.env`)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен из BotFather (обязательно) |
| `OWNER_TELEGRAM_ID` | твой ID — админ бота (обязательно) |
| `RCON_HOST` / `RCON_PORT` / `RCON_PASSWORD` | доступ к серверу для действий |
| `RCON_BIND` | команда при привязке (`<nick>` `<pass>` подставятся) |
| `RCON_RECOVERY` | сброс пароля (`<nick>` `<pass>`) |
| `RCON_LICENSE` | переключить режим лицензии (`<nick>`) |
| `RCON_2FA` | переключить 2FA (`<nick>`) |
| `RCON_KICK` | кикнуть аккаунт (обычно `kick <nick>`) |

Без RCON бот работает как «записная книжка» привязок, но действия на сервере
(`/recovery`, `/license`, `/2fa`, `/kick`) будут отключены — включи RCON в
`server.properties` (`enable-rcon=true`, `rcon.password=...`).

Шаблоны команд подбирай под свой плагин авторизации (AuthMe / LibreLogin /
LoginSecurity и т.п.). Пример для AuthMe:
```
RCON_BIND=authme register <nick> <pass>
RCON_RECOVERY=authme register <nick> <pass>
```

## Плагин

`plugin/dist/TelegramLink.jar` — при входе игрока показывает ссылку на бота
(из `bot_link` в `config.yml`). Больше от плагина ничего не требуется; вся
логика привязки и управления — в боте.

## Безопасность

- Не давай посторонним `BOT_TOKEN` и `RCON_PASSWORD`.
- `bot/.env` в `.gitignore` — не коммить его в публичный репозиторий.
- Токен можно сбросить в BotFather (`/revoke`).
